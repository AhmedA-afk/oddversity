## The short answer

The bootstrap estimates an estimator’s sampling behaviour by repeatedly resampling observed units with replacement and recomputing the estimator. It is useful when an analytic standard error is awkward, but it does not manufacture representativeness or independence. Resample the correct unit—user, session, group, or time block—and treat the empirical distribution as an approximation whose quality depends on sample size and design.

## Why this matters

Means have convenient formulas; medians, quantiles, ratios, and custom model metrics often do not. Bootstrap resampling gives a practical uncertainty workflow, provided the observed sample is a reasonable stand-in for repeated samples from the target process.

**Small incident (illustrative):** an analyst resampled individual events from users with many events and reported a narrow interval. The code was correct for iid events, but the product decision was about users; the unit of resampling understated dependence.

## How it works

Given data x₁,…,xₙ and statistic T, draw B samples of size n from the observed rows with replacement. Compute T* for each sample. The spread of T* estimates sampling variability; percentile endpoints can form an interval. The procedure approximates the unknown population distribution with the empirical distribution that puts mass 1/n on each observed row.

### Assumptions and derivation

The ordinary bootstrap assumes rows are exchangeable enough that iid resampling mimics the data-generating process. For clustered or time-series data, use cluster or block resampling. A bootstrap cannot correct selection bias because every resample repeats the selected sample’s composition. Small n, boundary statistics, and heavy tails may require specialised intervals or an analytic method.

## AI use

Bootstrap model metrics by user, document, conversation, or other deployment unit. Use it for uncertainty around retrieval recall, subgroup rates, or a custom threshold metric, and keep the resampling unit visible. Never claim that a narrow bootstrap interval proves production reliability.

## Worked examples and variations

### Example A — smallest happy path

**Input:** response times `[2, 3, 4, 5, 6]`, statistic = mean. **Mechanism:** sample five values with replacement many times and recompute the mean. **Output:** a bootstrap distribution centred near the observed mean 4. **Inspect:** compare its standard deviation with the analytic standard error s/√n. **Next decision:** use the bootstrap as a check, not as an automatic upgrade.

### Example B — meaningful variation

**Input:** the statistic is the median of `[2, 3, 4, 100, 101]`. **Mechanism:** resampled medians are discrete and may repeat 3, 4, 100, or 101. **Output:** an empirical uncertainty distribution without a convenient normal shape. **Inspect:** plot the bootstrap values rather than assuming symmetry. **Next decision:** report percentile or another interval with its method.

### Example C — boundary case

**Input:** sample `[0, 0, 0, 0, 0]` and statistic = positive rate. **Mechanism:** every ordinary bootstrap resample is all zeros. **Output:** zero-width uncertainty. **Inspect:** the bootstrap has no observed positive event to resample. **Next decision:** collect data or use a model-based method; do not read zero width as proof of zero risk.

### Example D — tempting counterexample

**Input:** event-level logs with 1,000 rows generated by only five users. **Mechanism:** ordinary row bootstrap treats events as independent. **Output:** intervals can be too narrow because user-level correlation is duplicated. **Inspect:** compare row bootstrap with user-cluster bootstrap. **Next decision:** resample the deployment unit.

## Computation and interpretation

```python
import numpy as np

rng = np.random.default_rng(11)
x = np.array([2., 3., 4., 5., 6.])
boot_means = np.array([
    rng.choice(x, size=x.size, replace=True).mean()
    for _ in range(10_000)
])
print(np.quantile(boot_means, [0.025, 0.975]), boot_means.std(ddof=1))
```

The interval is conditional on the five observed values and the iid resampling rule. Increase B to reduce Monte Carlo noise, but increasing B cannot fix a biased sample or wrong resampling unit.

## Two ways to see it

### Builder view

Bootstrap is a reusable test harness: one statistic, many plausible reassemblies of the observed units. It is especially useful for testing whether a metric is unstable under reasonable perturbations.

### Systems view

Resampling is a model of what could have varied. Choosing rows instead of users, or rows instead of time blocks, silently changes the uncertainty question.

## Hands-on

Create a bootstrap interval for the median of `[2, 3, 4, 100, 101]` with B=5,000 and a fixed seed. **Failure fixture:** bootstrap by drawing without replacement; every resample becomes a permutation with the same median. **Test:** the with-replacement distribution must contain more than one distinct median and its interval must be reproducible with the seed. **Reset:** restore `replace=True` and the original five-row fixture.

## What this does not solve

Bootstrap does not remove bias, create unseen modes, guarantee coverage, or justify iid rows. Percentile intervals can be inaccurate for skewed or boundary statistics. Validate the resampling design against how data actually arrives.
